# Соответствие проекта ТЗ «Техническое задание на BI»

Документ сопоставляет требования из `Техническое задание на BI.docx` с фактической реализацией проекта.

Легенда: ✅ выполнено · ⚠️ частично / требует действия · ❌ не выполнено

---

## 1. Цель проекта и архитектурные рамки

| Требование ТЗ | Статус | Где реализовано |
|---|---|---|
| Аналитическое решение для уровня запасов и оборачиваемости | ✅ | Витрины `datamart.turnover_metrics`, `datamart.inventory_monthly` |
| Парадигма классического DWH + BI по Кимбаллу | ✅ | Схема «звезда»: `dwh.fact_*` + `dwh.dim_*`, SCD2 для складов |
| Все ETL на стороне MS SQL Server | ✅ | Все шаги — хранимые процедуры в `sql/elt/`, `sql/datamart/` |
| Superset — только тонкий клиент | ✅ | Код BI в `superset/superset_config.py`: кеш выключен (`CACHE_TYPE: null`), только Live-запросы |
| Хранение/подготовка данных на стороне BI не допускается | ✅ | Все агрегаты заранее в витринах; BI читает готовое |
| Кастомные SQL-запросы в Superset поверх таблиц SQL Server | ✅ | Витрины доступны как datasets (`vw_*`), SQL Lab разрешён |
| Предварительно агрегированные витрины (тяжёлые агрегации в BI запрещены) | ✅ | `datamart.turnover_metrics` — KPI + MoM уже посчитаны, 4 уровня срезов |
