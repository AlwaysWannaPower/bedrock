# Руководство пользователя BI_DWH

Система BI_DWH — аналитическое решение для отслеживания **уровня запасов** и **оборачиваемости материалов** компании.

Это руководство описывает, как пользователю (от генерального директора до начальника склада) работать с дашбордом и как интерпретировать показатели.

---

## 1. Как открыть дашборд

1. Убедитесь, что система запущена (см. `README.md`, раздел «Быстрый старт»).
2. Откройте браузер и перейдите по адресу:

```text
http://localhost:8088
```

3. Войдите под своей учётной записью (по умолчанию после первичной инициализации):

```text
Логин:  admin
Пароль: admin
```

> Пароль рекомендуется сменить в настройках профиля (меню пользователя → Security → Change Password).

## 2. Из чего состоит дашборд

Дашборд единый для всех ролей — роль реализуется набором **фильтров**.

### Основные KPI (верхняя панель)

| Показатель | Что показывает |
|---|---|
| **Сумма запасов** | Стоимость запасов на конец периода (₽) |
| **Средний остаток** | Средняя стоимость запасов за период (₽) |
| **Оборачиваемость в разах** | Сколько раз запас «обернулся» за период |
| **Оборачиваемость в днях** | За сколько дней запас расходуется при текущем темпе |

Рядом с каждым KPI отображается **MoM (Month-over-Month)** — изменение к предыдущему месяцу в процентах:

```text
MoM = (значение_этого_месяца − значение_прошлого_месяца) / значение_прошлого_месяца
```

- `+10%` — показатель вырос на 10%;
- `−5%` — показатель снизился на 5%;
- для самого первого месяца MoM отсутствует (не с чем сравнивать).

### Графики

- **Динамика по месяцам** — линейный график метрики во времени.
- **Структура** — разбивка метрики по складам / дирекциям / материалам.

## 3. Метрики и формулы

Все метрики считаются **в хранилище** (витрина `datamart.vw_turnover_metrics`), а не в BI — дашборд лишь отображает готовые значения.

| Метрика | Формула | Примечание |
|---|---|---|
| Сумма запасов | `Σ (остаток_на_конец × цена_периода)` | Цена берётся за тот же отчётный период |
| Средний остаток (шт) | `(остаток_начало + остаток_конец) / 2` | Классика складского учёта |
| Средний остаток (₽) | `Σ (средний_остаток_шт × цена)` | |
| Расход в деньгах | `Σ (|расход| × цена)` | В исходных данных расход отрицательный |
| Оборачиваемость в разах | `расход_в_деньгах / средний_остаток` | Сколько раз запас обернулся за месяц |
| Оборачиваемость в днях | `30 × средний_остаток / расход_в_деньгах` | Условно месяц = 30 дней |

**Как читать оборачиваемость:**

- **в днях — маленькое значение** → запас быстро расходуется (высокая оборачиваемость, хорошо);
- **в днях — большое значение** → запас «лежит» на складе (низкая оборачиваемость, замороженные деньги);
- **в разах — высокое** → запас активно оборачивается.

Если знаменатель формулы равен нулю (например, не было расхода), показатель не выводится (`NULL`).

## 4. Роли и фильтры

Дашборд один, но каждый пользователь смотрит «свой срез» через фильтры:

| Роль | Как настроить фильтры |
|---|---|
| **Генеральный директор** | Фильтры не ограничивать — видна вся компания |
| **Директор по производству / закупкам** | Выбрать свою `Дирекцию` |
| **Начальник цеха** | Выбрать `Дирекцию` + `Цех` |
| **Начальник склада** | Выбрать свой `Склад` |
| **Менеджер по закупкам** | Выбрать дирекцию закупок / сырьевые склады |

Фильтры дашборда (Native Filters):

```text
Дирекция  (directorate)
Цех       (shop)
Склад     (warehouse_code)
Период    (месяц)
```

Фильтры работают иерархически: выбрали дирекцию → список цехов сузится до её цехов.

## 5. Типичные действия

### Посмотреть сумму запасов за последний месяц по компании

1. В фильтре «Период» выберите последний месяц.
2. KPI «Сумма запасов» покажет итог по компании (фильтры роли не заданы).

### Сравнить с предыдущим месяцем (MoM)

1. Рядом с KPI найдите поле MoM (например, `+3.2%`).
2. Если нужно точное значение — наведите курсор или откройте таблицу детализации.

### Найти склад с «зависшими» запасами

1. Постройте таблицу: строки — склады, столбец — «Оборачиваемость в днях».
2. Отсортируйте по убыванию: первые строки — склады с самыми медленными запасами.

### Разобраться, из чего состоит сумма запасов

1. Откройте dataset `vw_inventory_monthly` (SQL Lab или таблица на дашборде).
2. Отфильтруйте месяц и склад — увидите разбивку по материалам
   (`balance_end` × `price` = `stock_value`).

## 6. Детализация по материалам

Витрина `datamart.vw_inventory_monthly` содержит детализацию **месяц × склад × материал**:

| Поле | Описание |
|---|---|
| `balance_end` | Остаток на конец месяца, шт |
| `price` | Цена материала за период, ₽ |
| `stock_value` | Сумма запасов по материалу, ₽ |
| `expense_value` | Расход материала в деньгах, ₽ |
| `turnover_ratio` / `turnover_days` | Оборачиваемость материала |

Пример запроса для менеджера по закупкам (через SQL Lab):

```sql
SELECT
    month_key,
    material_id,
    unit,
    balance_end,
    price,
    stock_value,
    turnover_days
FROM datamart.vw_inventory_monthly
WHERE warehouse_code = N'0101'      -- свой склад
  AND month_key = 202512             -- интересующий месяц
ORDER BY stock_value DESC;
```

## 7. Частые вопросы

**Вопрос: Почему MoM пустой в первый месяц?**
Ответ: не с чем сравнивать — предыдущего месяца нет. Это норма.

**Вопрос: Почему в карантине много строк цен?**
Ответ: в исходных файлах заказчика ~25% строк цен — точные дубликаты. По ТЗ дубликаты помещаются в карантин, в анализ идут только уникальные строки (последняя версия выгрузки).

**Вопрос: Цифры не сходятся с учётной системой.**
Ответ: проверьте период цены и версию выгрузки. В витрине берётся цена **того же периода**, а не «текущая» цена. Также посмотрите `quarantine.*` — возможно, часть строк отбракована.

**Вопрос: Дашборд открывается дольше 5 секунд.**
Ответ: кеширование в Superset отключено по ТЗ (Live-запросы). Витрины предварительно агрегированы, поэтому фильтры работают быстро. При большом объёме данных проверьте индексы витрин.

## 9. Где посмотреть логи и ошибки

Для администратора:

```sql
-- Журнал ETL (все шаги)
SELECT * FROM elt.elt_log ORDER BY log_id DESC;

-- Ошибки
SELECT * FROM elt.elt_log WHERE status = N'ERROR' ORDER BY start_dt DESC;

-- Алерты (падали ли ETL)
SELECT * FROM elt.alert_queue ORDER BY alert_id DESC;

-- Карантин: что и почему отбраковано
SELECT error_reason, COUNT(*) FROM quarantine.turnover  GROUP BY error_reason;
SELECT error_reason, COUNT(*) FROM quarantine.prices    GROUP BY error_reason;
SELECT error_reason, COUNT(*) FROM quarantine.warehouses GROUP BY error_reason;

-- Статусы загруженных файлов
SELECT file_name, status, rows_loaded, loaded_at FROM elt.file_registry;
```
